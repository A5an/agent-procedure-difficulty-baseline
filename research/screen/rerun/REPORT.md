# Rerun of earlier screened methods under the baseline protocol (4 Oct 2026)

All numbers below come from the shared harness (prototype/screen/harness.py): same folds as the baseline, fold IRT from the repository cache, repository evaluator. The baseline ("adele") reproduces pooled rho 0.131 [0.027, 0.255]. Folds: 5 seeds x 5 folds for new_procedures, one pass for new_domain (SOPBench 7 domain folds, tau2 3). tauk_banking has a single domain and one procedure per task, so it has no new-process scenario; it contributes nothing to the pooled number. The random_cases scheme was not run (not part of the pooled number, the old screening did not use it either). No LLM calls were made (0 of 2,000): all PRECOG-style forecasts were already cached.

## 1. What was run

All features are the cached features of the earlier prototype (no recomputation was needed), written to features/<bench>/ in this folder by export_features.py (task order aligned to tasks.csv, column case_id). Only the model-fitting step is new: every method goes through the repository's ridge (their alpha grid) inside the seeded folds. The old numbers came from an older, unseeded code version.

- Hidden-state probe (Zhu et al. 2025, adapted). Qwen3-8B-Base (8-bit MLX), prompt = task statement plus a question "how likely is an AI agent to complete this task", feature = hidden state of the last prompt token after layer 18 or 36 (4096 dims; layer 36 is after the final norm). Exported as probe_L18.npz and probe_L36.npz (task_ids, X) and run through EmbeddingFeatureSource plus the baseline ridge. Deviation from the paper: a ridge on difficulty instead of their probe on correctness, 8-bit weights, a base model.
- Token entropy (Krsteski and Meyer 2026). 13 summary features of the token-entropy profile of Qwen3-8B-Base (8-bit MLX) reading the task context and a reasoning trace; the traces were generated by the earlier prototype's LLM (temperature 0) from the task context, so they use no outcome. Ridge on the 13 features. Deviation: the paper uses Claude Sonnet 4.6 traces with an unpublished prompt, 8-bit scorer.
- BPM process complexity (Cardoso CFC, size, AND/OR counts, nesting depth, connector degree and heterogeneity), SOPBench only, computed from the rule tree of the requested action (allowed by the brief, label: from the rule tree). Ridge on 9 columns. tau2 and banking have one policy for all tasks, so no per-task process. Because it exists in only two scenarios, it is scored in a separate SOPBench-only pool (second table); its pooled number is not comparable to the four-scenario pool.
- bge-base ridge: data/<bench>/features/bge_base_en_v1.5.npz from the repository, baseline ridge. Amortized IRT (Truong-style): methods.AmortizedIRT on the same bge source, default settings (column amortized_irt_bge).
- PRECOG-style forecast: cached zero-shot forecasts (success probability and 0-100 difficulty from gemini, temperature 0, one call per task, from the earlier prototype's llm_forecast.py); two columns, ridge. Complete cache for all 830, 278, 97 tasks. Deviation from PRECOG: it is a zero-shot forecast, not a trained forecaster.
- Fine-tuned small encoder: BAAI/bge-small-en-v1.5 with a linear head, mean pooling, 4 epochs, lr 5e-5, batch 16, max length 512, regression on the fold-IRT difficulty of the training tasks only (standardised), P = sigmoid(theta - beta_hat). Code copied unchanged from the earlier prototype (finetuned.py). Run on MPS. A fold took about 3 min on SOPBench (about 190 s) and 20-50 s on tau2, so the full protocol (5 seeds) was run, about 3.7 hours in total. One torch seed per fold (seed 0 inside the harness folds; the harness seeds torch with 1000*split_seed+fold).
- Combinations with ADeLe, for methods with pooled rho above 0.08 (probe L36 0.119, bge-base 0.113, fine-tuned 0.255): equal-weight logit average with the baseline, and a concatenated grouped ridge (the repository's GroupedRidgePredictor, penalty grid "Embedding" for the embedding, "LLM Judge" for ADeLe). The concatenated ridge is not defined for the fine-tuned encoder (it is not a feature source), so only its logit average was run. BPM (SOPBench-only pool 0.068) is below 0.08 but was also combined by logit average for completeness in the SOPBench-only table.

Verdict rule (EVALUATION_PROTOCOL.md section 8): "better" needs criteria 1 (mean rho higher and paired pooled CI above zero), 2 (no scenario with a paired CI entirely below zero), 3 (no held-out benchmark where significantly worse), 4 (Brier and log-loss skill not lower than the baseline), 5 (confirmation on a held-out benchmark). Criteria 3 and 5 cannot be assessed here, so "better" would at best be "better on 1, 2, 4". No method passes criterion 1. "worse" = the paired pooled CI lies entirely below zero.

Notes on the table.
- Fine-tuned bge-small has the highest pooled rho (0.255) but the paired CI to the baseline is [-0.026, +0.310], so it does not clear criterion 1. Its Brier and log-loss skill are below the baseline (-0.039 / -0.035 against 0.000 / -0.003): its ranking of tasks is better in tau2, its probabilities are less well calibrated. Per scenario paired CIs to the baseline: SOPBench NP [-0.123, 0.245], SOPBench ND [-0.147, 0.195], tau2 NP [0.084, 0.562], tau2 ND [-0.122, 0.675]. The gain comes from tau2 (0.321 and 0.473 against about 0.13 for ADeLe); on SOPBench it is at the baseline level (0.112, 0.114 against 0.120, 0.125). tau2 has 278 tasks with a small number of folds in new_domain (3), so tau2 ND is a noisy estimate.
- Its logit average with ADeLe (0.225, paired CI [-0.011, +0.195]) has positive Brier and log-loss skill (+0.047 / +0.040) and is the only combination whose scenarios are all at or above the baseline (worst +0.132 against +0.120); it still fails criterion 1 by a small margin on the interval.
- Hidden-state probe layer 36, bge-base and their ADeLe combinations sit at the baseline level (0.09-0.12) with intervals that include zero difference. Concatenated ridge is lower than the logit average in both cases.
- Layer 18, token entropy: worse than the baseline (paired CI entirely below zero). Zero-shot forecast, amortized IRT on bge: not better (pooled about 0). Amortized IRT is unstable (tau2 ND -0.293, Brier skill -0.185).
- BPM complexity: on SOPBench only, 0.068 against 0.123 for ADeLe in the same two scenarios; combined with ADeLe 0.118, no gain.


Fine-tuned encoder, old preliminary number (new_domain only, seed 0 of three single-seed runs): SOPBench ND 0.133 (other seeds 0.088, 0.120), tau2 ND 0.456 (other seeds 0.141, -0.154). Clean rerun: SOPBench ND 0.114, tau2 ND 0.473, with the NP scenarios 0.112 and 0.321 that were not screened before. The old seed-to-seed spread on tau2 ND is large, so the clean tau2 ND value should not be read as stable.

Differences between old and clean runs are mostly small (|diff| of pooled mean below 0.02 for every method). The larger per-scenario shifts are probe L36 on tau2 NP (0.150 to 0.218), llm_forecast on SOPBench ND (0.058 to -0.008), probe L36 on SOPBench ND (0.121 to 0.107). The pooled ordering is unchanged: ADeLe 0.131, probe L36 0.119, bge-base 0.113, then entropy, forecast and amortized IRT around zero, probe L18 negative.

## 3. What could not be run, and caveats
- BPM metrics for tau2 and tauk_banking: no per-task process is visible (one policy for all tasks). It is scored on SOPBench only.
- tauk_banking: no new-process scenario exists (single domain, one procedure per task), so it is not in any pool; criterion 3 (held-out benchmark) and criterion 5 (frozen confirmation) are therefore not assessed.
- The concatenated ridge for the fine-tuned encoder (not a feature source).
- Hidden-state and entropy features were computed once by the earlier prototype (8-bit MLX Qwen3-8B-Base) and not recomputed; the old unseeded code only affected fold assignment, ridge/IRT randomness and the torch models, not these features.
- The fine-tuned encoder was fitted with one torch seed per fold; its run-to-run noise was not measured here.
- Nothing was tuned on test folds. The 0.08 threshold for combinations was set in the task statement.
