# Контекст работы 2–4 ноября 2026

Сводка всего, что сделано после передачи ресерча, чтобы можно было разобраться в деталях без автора. Каждый опыт
лежит в `research/screen/<папка>/` этого репо: `PREREG.md` (план, записан до запуска), `REPORT.md` (результат), код, выходы
`*.out`, `results*.json`. Отклонения от плана записаны в `REPORT.md` или `DEVIATIONS.md` той же папки. Полные логи
разговоров (`runs/msgs/`) в архив не вошли, они весят сотни мегабайт; исходы эпизодов (`runs/*.jsonl`) вошли.

## Задача

До внедрения понять, справится ли LLM-агент с типом задач (процедурой), и по этому решать, отдать тип задач агенту,
агенту с проверкой или человеку. По замечанию Зангира главная метрика теперь процент успеха, которому можно верить
(Brier, калибровка, доля задач, которые можно отдать при пороге, и успех среди них), а не ранговая корреляция.

## Главное в трёх строках

1. Чтение описания задачи (признаки, оценка моделью) упирается в 0.2–0.35. Процент даёт только прогон похожих задач
   («проб»): с пробами по прошлым разговорам при пороге 90% агенту уходит 36–58% задач, и он решает 91–96% из них.
2. Пробы дважды: их эпизоды учат монитор разговора, роутер с эскалацией экономит около $2.3 на задаче против «всё
   людям»; повторено на 30 новых семействах TauIndianBank по заранее записанному плану.
3. Открытая дыра: процедуры без истории. Пробы по одному документу дают плохой процент. Первый опыт, где прошлые
   разговоры сочиняет Opus, даёт пригодный процент для агента Sonnet, но выборка маленькая.

## Как воспроизвести

- Данные снаружи архива: TauIndianBankBench (github npci/TauIndianBankBench, коммит 1ccb64f, данные с HF
  NPCI/tau-indian-banking) в `prototype/data/external/tauindianbank/code` с venv через uv; SOPBench и прогоны прошлых
  раундов (`ideas2`, `ideas5`, `baseline/data/sopbench`) из основного репо. Пути в коде относительные к
  `prototype/screen/`.
- Gemini идёт через локальный прокси (`tib/proxy.py`, `synth/proxy.py`, `combo_rep/proxy.py`) к Vertex AI с
  `gcloud`-токеном; у каждого опыта свой `ledger.jsonl` и потолок трат `cap_usd.txt`. Проект Google Cloud берётся из
  `gcloud config`, в логи не пишется.
- Claude идёт через `claude -p` по подписке (`synth/gen.py`, `claude_agent/claude_proxy.py`), без инструментов и без
  CLAUDE.md (`--tools "" --setting-sources ""`).
- Анализ бесплатный и запускается из папки опыта: `python3 <скрипт>.py`.

## Пути

Код этих опытов писался в `prototype/screen/` основного рабочего дерева и ссылается на соседние папки через
`Path(__file__).parent.parent`, поэтому внутри `research/screen/` соседние ссылки работают. Внешние данные
(TauIndianBankBench, SOPBench) код ищет в `prototype/data/external/` относительно корня рабочего дерева; в этом репо
положите их туда или поправьте пути. Папка `transfer` из этого раунда переименована в `transfer_agents`, чтобы не
конфликтовать со старой `research/screen/transfer`.
