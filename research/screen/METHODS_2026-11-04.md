# Методики предсказания «справится ли агент»: что проверено и что дальше (4 ноября 2026)

Цель: до внедрения дать процент успеха агента на типе задач (процедуре), которому можно верить, и по нему решать,
отдавать ли тип задач агенту. Метрики: Brier, калибровка, доля задач, которые можно отдать при пороге 90%, и успех среди
них (папка `metrics/`).

## Уже проверено

| Методика | Что дала | Где |
|---|---|---|
| Чтение описания задачи моделью или признаки текста | ρ 0.2–0.35 на SOPBench, 0.23–0.51 на свежих бенчмарках | ideas*, c_lad, D |
| Пробы по документации | TIB: Brier skill +0.02 (3.8 flash) и +0.12 (2.5 flash); отданные агенту задачи решены лишь на 73–86% | tib, metrics |
| Пробы по прошлым разговорам | TIB: skill +0.26/+0.36, при пороге 90% отдаём 36–48% задач с 91–93% успеха; связь с реальностью после поправки на шум ≈ 0.9 | tib/seeded, combo_rep, metrics |
| Модель MF, сжатие, перекалибровка | на TIB не лучше сырой доли проб; на SOPBench MF помогает при 2–4 пробах | mf, calib |
| Добавить к пробам монитор, пробы второго агента, пробы по документации | процент не улучшают; пробы второго агента чуть помогают только пробам по документации | pimprove, calib |
| Монитор эпизода на пробах | для роутера с эскалацией полезен (−2.27 $ на кейс), для процента процедуры нет | combo, combo_rep |
| Предсказание отдельного кейса по похожести на пробы | внутри семейства AUC 0.56, не работает на шаблонных семействах | caseknn |
| Реальные кейсы в теневом режиме | 2–4 кейса хуже 20 проб | autonomy |

Вывод: процент уже настолько хорош, насколько похожи пробы на реальные задачи. Остаётся улучшать саму похожесть.

## Что дальше, по убыванию пользы

1. **Синтетические «прошлые разговоры».** Сильная модель сама пишет реалистичные прошлые разговоры процедуры, по ним
   пишутся пробы. Если это дотянет до уровня настоящих прошлых разговоров, у нас метод для процедур без истории.
   Идёт сейчас бесплатно на Claude (`claude_agent/`, опыт 8): агент Sonnet, клиент Haiku, пробы пишет Opus, три вида
   проб (документация, настоящие прошлые разговоры, синтетические).
2. **Агент другого семейства.** Тот же опыт 8 заодно проверяет, держится ли всё на Claude-агенте, а не только на Gemini.
3. **Сколько проб нужно для гарантии.** Проверено (`seqtest/`): последовательная остановка тратит в среднем 4–6 проб
   на процедуру вместо ~30 и отдаёт агенту столько же задач с тем же успехом (68% задач при 94% успеха против 61% при
   95% на всех пробах). Пограничные процедуры получают больше проб, очевидные решаются после нескольких.
4. **Детектор дыры в документе.** Проверено (`docgap/`), не работает: Sonnet ставит почти всем процедурам 7–8 из 10,
   связь с ошибкой проб по документации ρ +0.19 [−0.08, +0.43].
5. **Пробы-ловушки.** Просить генератор писать самые трудные реалистичные варианты процедуры, а потом поправлять
   уровень. Может поднять различимость там, где обычные пробы все проходят.
6. **Перенос с дешёвого агента.** Проверено (`transfer/`): пробы другого агента дают чуть больше половины
   информации (Brier skill +0.15 против +0.26 у своих проб), объединение со своими ничего не добавляет. Каждого
   агента надо пробовать самого.
7. **Кейс до запуска по данным клиента.** Проверено (`caseknn/caserec.py`), не работает: внутри семейства AUC 0.51.
   Какой кейс процедуры провалится, до запуска не видно; по E8 два одинаковых прогона расходятся на 11% кейсов,
   так что внутри процедуры заметная доля провалов это случайность прогона.
